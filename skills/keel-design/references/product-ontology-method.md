# 产品概念建模方法

借鉴 BKN Foundry 的对象类、关系类、行动类和风险类。先从实际产品路径提取并校正四类定义，再用已定义的行动表达核心业务流程。 [BKN 引擎手册](https://github.com/openbkn-ai/bkn-foundry/blob/main/help/zh/manual/bkn.md)

1. 选一条主路径和一条有差异的路径。第二条可以改变同一对象的角色、复用已有对象或触及失败。已有产品先核对术语与事实来源，把拟新增的语义标为提案。
2. 按四类定义记录实际含义。

   | 类别 | 要回答的问题 |
   | --- | --- |
   | 对象类 | 一个实例代表什么？事实从哪里读取？什么变化会产生新的实例或版本？ |
   | 关系类 | 哪个对象以什么角色关联哪个对象？关系何时建立，能否缺省或重复？ |
   | 行动类 | 谁可以对哪个对象做什么？需要什么输入和前置条件？会改变或产生什么？ |
   | 风险类 | 行动在什么条件下可能造成什么后果？何时阻断、要求确认或提示？失败后如何处理？ |

3. 用第二条路径检查对象边界。同一实例只改变用途时，用关系表示角色。同一生命周期里的变化用状态表示。需要独立身份、查询、授权或追溯，且现有对象和关系无法表达时，再拆出新对象。
4. **用本体行动串起核心业务流程。** 从业务触发到可观察的终点，按执行顺序串联已定义的行动。每个关键步骤引用行动、执行者、作用对象和前置关系，说明产出或状态变化怎样进入下一步。用已定义的风险约束标出分支条件、失败时保留的状态，以及恢复到哪一步或在哪里结束。
5. 把对象关系、核心业务流程和产品规则写回已有章节，并核对受影响的验收。流程图可引用对应的对象和行动，规则与验收沿用原有落点和编号。跨需求复用的模型由项目维护一份。
6. 工作流要求 HTML 时，在同一页提供可直接定位的对象关系和核心业务流程。用相同的对象及行动名称串起两处，展示主路径、关键阻断及恢复去向。页面随正文和相关验收一起维护，落点按当前工作流约定。

例如，训练完成后，授权人员**登记模型**，产出模型版本。评估人员**提交评估**时引用这个版本作为基线，校验通过后建立基线关系并发起评估。引用权限不足时阻断提交，保留草稿供改选。结果就绪后，评估人员**查看比较结果**，同口径时展示差异，口径不一致时说明无法直接比较。登记产物和评估基线是同一个模型版本通过两种关系承担的角色。
