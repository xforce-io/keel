# 产品概念建模方法

借鉴 BKN Foundry 的对象类、关系类、行动类和风险类。用实际产品路径提取并校正四类定义。 [BKN 引擎手册](https://github.com/openbkn-ai/bkn-foundry/blob/main/help/zh/manual/bkn.md)

1. 选一条主路径和一条有差异的路径。第二条可以改变同一对象的角色、复用已有对象或触及失败。已有产品先核对术语与事实来源，把拟新增的语义标为提案。
2. 按四类定义记录实际含义。

   | 类别 | 要回答的问题 |
   | --- | --- |
   | 对象类 | 一个实例代表什么？事实从哪里读取？什么变化会产生新的实例或版本？ |
   | 关系类 | 哪个对象以什么角色关联哪个对象？关系何时建立，能否缺省或重复？ |
   | 行动类 | 谁可以对哪个对象做什么？需要什么输入和前置条件？会改变或产生什么？ |
   | 风险类 | 行动在什么条件下可能造成什么后果？何时阻断、要求确认或提示？失败后如何处理？ |

3. 用第二条路径检查对象边界。同一实例只改变用途时，用关系表示角色。同一生命周期里的变化用状态表示。需要独立身份、查询、授权或追溯，且现有对象和关系无法表达时，再拆出新对象。
4. 把结论写回已有对象关系、交互和产品规则，并核对受影响的验收。现有流程图、对象表和验收编号可以直接引用。跨需求复用的模型由项目维护一份。

例如，训练产生的模型登记为一个版本。同一个版本可被后续评估引用为基线。用两条路径确认模型版本的身份始终一致、记录角色的关系各自独立。候选与基线使用的评估口径不一致时，比较结果应明确说明无法直接比较。
