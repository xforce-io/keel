# 项目知识

优先使用项目已有文档位置、命名和格式：领域术语归 glossary，设计意图和决定归设计文档或 ADR，用户路径归 verify 功能地图，执行约束归有效 AGENTS.md。不要复制既有事实源。没有约定时，跨文件机制可放 `docs/knowledge/<topic>.md`；可选 `README.md` 列主题、适用问题及链接，少量文档无需索引。不要安装时创建目录或强制每次任务写文档。

一篇围绕一个稳定主题，精简说明：

```markdown
# 主题

## 适用范围
覆盖与不覆盖什么。

## 当前机制
用事实解释主要步骤及跨文件关系。

## 入口与依据
- 描述：`项目内源码路径`（必要时附符号）

## 注意事项
约束、失败处理或容易遗漏的边界。

## 相关资料
链接设计意图、术语和功能地图；没有可省略。

## 核对记录
最近核对日期及当时 commit；工作区有未提交变化时注明。
```

日期与 commit 只是核对线索，不证明现在仍正确。记录当前源码依据，不存秘密、原始会话或无依据推测；区分设计意图与实际行为。仅沉淀跨模块、难以重新发现且可能复用的信息。how 给具体建议，不写文件；后续实现按授权范围维护相关文档。
