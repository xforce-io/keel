# Accepted 指令与 skill 评估

有行为改动候选时读本文件。不要用 `no-change` 丢掉仍应进 Backlog 的产品问题。

## skill 行

- 先改本会话用过的现有 skill。  
- 该触发却没触发 → `tune description`，不要复制一份新 skill。  
- `new skill` 仅当没有合适的家、模式会复发、且值得独立成 skill。  
- 读目标 `SKILL.md` 后再接受正文修改；已写清楚则 Rejected（`already-covered`），那是执行问题。

## AGENTS.md 行（Accepted 至多一条）

候选必须同时：有直接证据、可复用、持久、可执行（触发 + 期望行为）、现有规则未覆盖。

全局额外：两次独立任务证据；不绑死某一仓库/框架/宿主；跨项目的边界或协作原则；收益能抵每次会话的上下文成本。

最小化顺序：已覆盖不改 → 删过期 → 合并进现有规则 → 收窄/重写 → 最后才新增。正文尽量一条短指令。解释留在提案里。

项目级选仓库里最窄的适用 `AGENTS.md`。全局只改检查器给出的规范源。
