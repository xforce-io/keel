# Issue routing

Resolve the repository and hosting platform first. Read the Issue, acceptance criteria, linked
design, branch, PR/MR, and CI state using read-only operations. Follow the effective `AGENTS.md`
Issue schema and terminology.

Choose the next legal stage from observed evidence. Do not recreate an Issue, design, branch, or
review that already exists. If the target Issue is ambiguous or required acceptance criteria are
missing, ask one concise question.

When a later increment resumes the same Issue, read the latest `S1…Sn` acceptance table on the
Issue or PR/MR before acting. Treat `pass` rows as preservation checks if this change can touch
them; do not drop a story id.
