# 何时写设计

keel 任务里要不要写 L1 / L2 以本文为准，不以 AGENTS.md 的「L1 触发」列表为准。
章节结构、事实源、批准用语仍套用有效 `AGENTS.md`。

必须写 L1（任一）：

- 公共 API / CLI / 事件 / 配置契约
- 跨模块或存数形态
- 生产运行时依赖，或用户启动的产品进程
- 新权限或安全边界
- 用户主路径或生命周期门禁
- 人或评审要求

跳过写 L1（命中则不写；压过「新依赖 / 新进程」，当且仅当不进生产运行时）：

- 无契约的单模块重构
- 纯测 / 文档 / 文案 / 运维
- 测试-only / 开发依赖
- 验证用浏览器或模拟器（Drive 结束即关）
- 按已 Approved design 实现

必须写 L2（L1 已有，任一）：

- 公共接口
- 跨模块或迁移 / 新存数
- 生产运行时依赖
- 权限 / 多租户 / 安全模型
- L1 明确要求

未命中 L2 则不建 `docs/design/`。
吃不准是否必须写 L1 → 写。
