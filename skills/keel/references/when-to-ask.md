# 何时问人

只按本表匹配，不临场发明一类「感觉要问」。
keel 任务里要不要问人以本文为准，不以 AGENTS.md「评审通过后实现」为准。

必须问（缺授权则停）：

- force-push 到共享分支
- 合入默认分支（授权=审查 PASS 且 human: optional，或人明确说合入）
- 部署
- 删生产数据
- 对客消息

默认不问（做完呈交，人事后纠偏）：

- 写代码、改测试、改文档
- 测试-only / 开发依赖
- 验证用浏览器或模拟器（Drive 结束即关）
- 开 feat/* 或 bugfix/*、开 PR
- 团队聊天、改 Issue / PR 评论、跑检查

吃不准是否落在「必须问」→ 停，问一次。
「必须问」以外不得改口为停。

## 和其它门禁

四件事分开问，不要合成一个「要不要人」：

| 问 | 机制 | 谁判 |
|---|---|---|
| 现在能不能动手 | 上文两张表 | 按表匹配；吃不准就问 |
| 要不要写 L1 | `when-to-write.md` | 写不写 ≠ 问不问 |
| 写完 L1 是否停 | 流程：`design` 停；`dev` / `end-to-end` 继续 | 用户点名的流程，不是本表 |
| 合入前要不要人看审查 | `keel-review` 的 `human: required` 或 `human: optional` | Reviewer；硬条件不得 `optional` |

本表「合入默认分支」的授权就是审查 `PASS` 且 `human: optional`（或人明确说合入）。`keel-design` 不另给 `human:` 字段。
