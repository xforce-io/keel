# keel 决策行为样例

四组脱敏合成输入，供维护者重放关键决策；不新增产品规则、模型 API、执行器或自动门禁。输入不是实际仓库状态，也不是可执行的交付证据。

| 输入 | 覆盖的决策 |
|---|---|
| [01-doc-only.md](inputs/01-doc-only.md) | 纯文字改动的设计适用性与确认 |
| [02-investigate-bug.md](inputs/02-investigate-bug.md) | 修复前调查及已确认产品契约 |
| [03-review-retry.md](inputs/03-review-retry.md) | 新候选复验、历史证据与审查轮次 |
| [04-human-approval.md](inputs/04-human-approval.md) | 当前候选人工批准前停点 |
| [04-human-approval-followup.md](inputs/04-human-approval-followup.md) | 同组固定后续回复，批准后的恢复 |

判断标准单独放在 [expectations.md](expectations.md)，只交给评估者，不能放进受测 Agent 上下文。

## 重放

1. 冻结当前候选，按仓库 verify-keel 手册 scratch 安装和 Doctor，记录实际 skill 来源；不得对真实家目录安装或卸载。只测这些决策样例，不因此运行无关全图功能。
2. 每组使用独立、未读判断标准的真实 Agent 上下文。给它对应输入、当前已安装 `keel` 的入口及按需读取的环节；四组不要互相串上下文。通用要求仅为：读取适用合同，依据给定合成状态给出下一步和理由；材料不足时如实说明；不修改文件、不操作真实平台。不要把预期答案写进提示词。第 4 组先保存首次输出，再向同一上下文追加固定 followup。
3. 另由未产生受测回答的评估者，结合判断标准、对应合同和实际输出逐项判断。关键词出现不等于动作合理；禁止只靠脚本匹配“skip”“BLOCKED”判通过。偏离标准时保留实际输出，不事后改答案标准迎合结果。
4. 原始输入、输出和判定保存到 `.agents/verify-runs/<issue>/`：候选 SHA、样例版本（Git blob 或摘要）、读取的 skill、宿主/模型及其可观察来源、时间、每组 `pass / fail / blocked / not_run`、依据和缺口。未知用量写未知，不补零；保留失败尝试。不要把私人会话、凭据或模型输出提交到样例目录。
5. 按手册清理本次 scratch，保留证据。规则变更后先判断样例契约是否仍适用；确需改标准时记录对应合同变化，不能为获得通过而静默改标准。

## 证明范围

这些是决策行为评测：可观察选择、理由、诚实性和恢复条件。它们不证明实际改代码、复现成功、测试执行、Reviewer 身份认证或平台合入，也不等于完整端到端验收。一次宿主/模型重放不能证明其他模型、宿主或所有输入都正确。现有 unittest 与真实业务驾驶验证继续按原合同执行。
