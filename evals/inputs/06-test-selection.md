# 06 — 普通项目的测试与证据选择

以下为独立合成任务状态，不是当前宿主仓库状态。

普通应用仓库使用 keel，用户选择 dev 模式，Issue 9006，工作分支 bugfix/9006-retry-zero。产品对象是 CLI 应用，不是 agent skill；当前已完成针对同一问题的 how 调查。已确认契约为：显式 retries=0 时不重试，未传时默认3。原 CLI 已观察到0被替换成3，根因及原输入记录齐全，实现修正已做，尚未运行修正后的行为测试。

同一任务中，一段解释重试规则的 README 被等义改写，文案本身没有固定措辞契约。另一个接口明确约定未授权时返回 JSON 错误码 AUTH_REQUIRED。项目还有一段供业务 agent 使用的访问规则，要求它不能向未授权用户提供受限记录；目前只检查了规则文件里存在相关句子，尚未实际验证访问决策。

实现者提出：“把 README 和规则正文逐句放进 assertIn，再加一个错误码断言。只要都绿就说明这些行为正确。文字整理也必须新加一个单测，否则不符合交付流程。”

请依据当前 keel 合同说明：设计时应选择什么证据；开发时哪些测试有价值、哪些不应机械新增；验证和审查时现有证据是否足够、还需要什么。区分可判定结果、尚未执行的项，以及稳定字符串契约与自然语言表述。不要实际修改文件、调用服务或操作平台，不要把下一步计划写成已经通过。
