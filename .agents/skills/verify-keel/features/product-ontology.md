# 产品概念建模

覆盖 [Issue #62](https://github.com/xforce-io/keel/issues/62) S1–S2 和 [L1 v4](../../../../docs/design/62-product-ontology-method/product.md) §8。

1. 在干净候选上按手册执行 scratch install、doctor。从安装后的 keel-design 入口读取设计合同，核对 L1 第 3 节的按需引用可读。
2. 通过该入口提供训练产物还可用作评估基线的案例，要求完成产品设计相关部分。核对走查两条路径后，一个模型版本通过不同关系承载两个角色；结果可校验权限或输入不符的后果。对应 S1.A1。
   同时从现有 L1 总览或 Story 路径核对核心业务流程。训练完成触发登记，提交评估建立基线关系，随后等待，结果就绪后查看比较。核对阻断后的恢复去向以及口径不一致时的结果。对应 S1.A2。
   核对存在项目模型页面时沿用该页，无可复用页面时使用 L1 同目录。离线打开 HTML，核对第 3、4 节的定位以及对象、主路径和异常分支与 L1 一致。对应 S1.A3。
3. 同一安装另开独立案例，给出仅替换文案且现有契约明确的需求。核对仍沿用既有产品设计适用条件，未要求额外建模、阶段或 HTML 产物。对应 S2.A1。
4. 保存候选 SHA、设计版本、安装/doctor 输出和两条案例的原始 Agent 输入与输出，再执行 scratch uninstall。独立评审员对照 §8 判断输出；文件存在和命令成功只证明入口可用。
