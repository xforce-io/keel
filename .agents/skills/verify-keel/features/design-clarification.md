# 按需澄清产品取舍

关联 #35 S1–S4 与 [L1 v1](../../../../docs/design/35-design-clarification/product.md) §8 的八项必需验收。这里验证真实 coding-agent 会话，不把静态合同检查当模型行为证明。

## 用户入口（全部走）

1. 在干净候选上按手册用 scratch home install、doctor；从 scratch library 的 keel-design/SKILL.md 读取 clarification.md、design-contract.md 及确认/触发规则。核对相对引用在安装入口可读，记录候选 SHA。
2. 用独立隔离场景从真实 coding-agent 的小修复入口执行 S1.A1：提供已确认允许 0 的契约和把 0 替换为默认值的缺陷，观察调查、修复与原路径验证，不要求新访谈或新设计。保留工具原始输出和 diff。
3. 从已安装设计 skill 入口执行 S1.A2–A3、S2.A1、S3.A1–A2：让 agent 读取可查事实，提供含上游/下游依赖的未决产品行为；实际运行至少两轮，依次给预先编写的测试用户回复。回复覆盖失败保存、默认自动重试 0、手动最多 3 次、仅管理员、禁止自动执行，再改变失败保存的上游决定。检查每轮问题、推荐/代价、等待行为及设计与验收的对应修订。脚本回复仅是测试输入，不充当本票用户的真实批准。
4. 从设计入口执行 S2.A2：先提出需要体验的布局选择但不提供原型，观察保留未决；再运行可操作原型或取得真实操作记录并提供给同一会话，观察决定引用该依据。未取得依据不能判通过。
5. 核对 S4.A1：以上会话沿用已有确认与交付边界，不新增强制批准；随后 scratch uninstall 并清理本次隔离场景，保留证据。原有 design-contracts.md 安装引用路径受影响时一并检查。

## 证据与判定

在 `.agents/verify-runs/35/` 保留候选 SHA、设计版本、安装/doctor/卸载原始输出、模型运行宿主和可观察模型、每轮完整输入输出及工具调用、测试用户回复、场景前后文件与运行结果、原型操作记录。逐项填写 S1.A1–S4.A1，八项全 pass 才汇总 S1–S4 pass。实际会话未执行、模型不遵守、缺条件分别记 not_run、fail、blocked；不能用 grep、硬编码对话或模型自称代替证据。效果仅覆盖本次宿主/模型和场景，不证明所有模型行为。
