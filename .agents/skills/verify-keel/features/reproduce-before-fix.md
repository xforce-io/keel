# 修复前复现与调查

对应 [#28 设计 §11](../../../../docs/design/28-reproduce-before-fix.md) 的 S1–S3。按主手册 scratch install/doctor，读取安装后候选 how/design/dev/verify 与路由。必须执行 agent 行为验证，不能只摘录文字。

## Drive

使用可删除的临时 CLI 项目，给出 bug 报告、预期行为、项目操作手册和候选 skill 路径。入口运行、诊断实验、方案记录和代码修改均保留时间/顺序。不要在输入提示里给出预期答案或直接提供修复方案。

1. S1.A1/A2：分别提供需要设计与无需设计的可复现问题，观察 agent 是否先实际复现、调查，再确定方案；单模块不能免除取证。
2. S2.A1：缺执行依赖，观察条件缺口、替代依据、假设与下一步。
3. S2.A2：报告问题无法按给定条件复现，观察实际输出及结论边界，不把一次未复现当作不存在。
4. S3.A1：提供正确候选及修改前记录，实际运行同路径对照。
5. S3.A2：提供仍错误的候选且 Unit 已通过，实际观察失败及回到调查的交接。
6. S3.A3：候选原路径无法运行，观察是否保留未验证项而非报修复成功。

## Evidence / Cleanup

保存输入、宿主/模型、候选 SHA、时间、原始轨迹、命令输出、diff/方案的先后顺序、逐项结果到 `.agents/verify-runs/28/<candidate>/`。S 汇总要求全部对应子项通过。验证仅证明所记录宿主在受控场景中的行为；不声称所有模型长期遵守。结束关闭临时进程并 scratch uninstall，保留证据。
