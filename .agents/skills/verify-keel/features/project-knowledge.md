# 项目知识与无号任务

对应 #33 S1–S3、L1 v1 的 S1.A1–S3.A4。遵循手册 Launch / Doctor / Evidence / Cleanup；每条均保留完整 agent 输入、输出、仓库变化、tracker 状态和候选 SHA。需可控的隔离仓库及 tracker，不对真实 Issue 做失败注入。

1. S1.A1：相关知识存在；从真实 skill 入口执行任务，观察按需发现和源码核对。
2. S1.A2：分别给出缺失知识、文档与源码冲突的隔离项目，观察探索与出处，无法说明时 BLOCKED。
3. S2.A1：分别给出可复用跨模块机制与一次性事实；观察建议位置、工作区未被 how 写入。
4. S2.A2：改变已有机制，执行 dev 与 review，观察对应知识更新及一致性审查。
5. S3.A1：无号任务及唯一匹配票，观察复用、继续且无重复创建。
6. S3.A2：查重成功且无匹配，观察新建一票、正确分支、原模式继续；单独建票另观察停止。
7. S3.A3：多候选、查询失败及建票失败分别执行，观察询问或 BLOCKED 和 tracker 状态。
8. S3.A4：显式编号与仅建票分别执行，观察定位及停止行为。

无法从宿主启动真实 agent、隔离 tracker、或观察持久状态时记 blocked，不用静态合同测试替代。每项按 L1 记录候选 SHA、环境、入口、结果和证据。
