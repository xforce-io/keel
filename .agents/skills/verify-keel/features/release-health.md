# 发布的即时健康判定

文件/skill 入口，使用手册的 scratch install / doctor / cleanup。不得部署或访问线上环境；本文件只验证挂载合同可读且边界可判定，不声称已经观察到生产结果。

## 用户入口（全部走）

1. 安装后确认 library 中 `keel-release/SKILL.md` 指向当前仓库，并读取挂载文件。
2. `local-skill find keel-release` 可发现该 skill，读取查找结果指向的合同。
3. 对照本仓库 `skills/keel-release/SKILL.md` 原文，逐项记录下述验收；不得把文本核对写成线上验证通过。

## 验收条目

- #22 S1：有部署阶段时，合入前须能从 runbook 确认目标环境、实际运行版本的判定方式、健康标准和有限观察时限；本次报告含目标环境、实际版本及证据、检查依据、观察时限、结果和结束状态。部署命令成功不能代替健康结果。
- #22 S2：缺必要依据、部署/健康检查失败、超时或无法确认实际版本均 `BLOCKED`；仅按已授权的 runbook 处理回滚，报告已执行处理、观察状态和下一步，不宣称端到端完成。
- #22 S3：达到 runbook 通过标准后本次 release 结束；持续监控或故障调查另行处理。项目无部署阶段时，合入后明确说明没有线上健康检查。

保存挂载、查找输出和各条合同摘录到 `.agents/verify-runs/22/`；结束按手册卸载 scratch，保留证据。
