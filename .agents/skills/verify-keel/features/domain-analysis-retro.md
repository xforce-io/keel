# 领域事实、设计反例与代码库复盘

覆盖 [Issue #66](https://github.com/xforce-io/keel/issues/66) S1–S3 和 [L1 v1](../../../../docs/design/66-domain-analysis-retro/product.md) §8。

1. 从干净候选用 scratch install 和 doctor 启动，确认 library 下三个 Skill 入口及相关参考均可读。
2. 从安装后的 `keel-how` 调查订单与出库记录中的「取消」。一个案例有书面契约且实现存在差异，另一个仅提供可读源码。在两次交接中对照源码核对术语范围、状态交接、规则责任和未确认意图。对应 S1.A1–A2。
3. 从安装后的 `keel-design` 处理仓位分配案例。先提供带有稳定规则 ID 的 L1 与并发或失败路径，再提供保持外部行为、仅调整内部责任且有 API 契约的独立案例。保留反例、是否需要澄清、所选设计路径、实际引用及责任和恢复结果。对应 S2.A1–A2。
4. 从安装后的 `keel-reflect` 复盘同一项已完成工作。输入包括有现场证据且仍存在的重复规则、无可核验影响的命名偏好、当前还没完成的验收。检查仅第一项成为有验收依据的草案，现有未完成项仍留在原任务，未执行建票。对应 S3.A1–A3。
5. 在 `.agents/verify-runs/66/` 保存候选 SHA、设计版本、环境和时间、原始会话输入输出、工具记录及每条判定。评估者对照 L1.8 复核产出与禁止结果。运行 scratch uninstall 并保留证据。

命令成功和文案检查只证明入口可达。行为结论以实际 Skill 会话和独立评估为准。
